## Class loader

As the name suggests, it is responsible for dynamically loading Java class files (.class) into memory during runtime.

## Runtime Data Areas (Heap, Stack, Method Area, PC Register)

**Heap**

Stores all objects and arrays created using _new_ keyword.

**Stack**

Each thread has its own stack. A stack stores method calls, local variables, primitive values and references.

**Method Area**

It basically stores class level information like blueprints, metadata and static data.

**PC Register**

Each thread has its own PC Register. It stores the address of the next instruction to execute.

## Execution Engine

It is the central component of JVM responsible for executing the compiled Java bytecode (.class files) by converting it
into machine-readable native code.

## JIT Compiler vs Interpreter

JIT compiler translates frequently executed code into native machine code for quick execution.

While Interpreter is responsible for executing source code or bytecode line by line during runtime.

## What does “write once, run anywhere” mean?

Bytecode is a platform independent intermediate code generated by the JAVA compiler (javac) and stored in .class files.

This .class file can run on:
- Windows
- macOS
- Linux

as long as JVM is installed. Thus being platform independent.
